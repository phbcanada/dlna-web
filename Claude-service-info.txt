New file: dlna-web.service, plus a step-by-step walkthrough in README_WEB.md under "Running it as a boot-time service." Short version:

Put the project at a permanent path (e.g. /home/pi/dlna-web)
python3 -m venv venv && venv/bin/pip install -r requirements.txt
Test manually with venv/bin/waitress-serve --host=0.0.0.0 --port=8080 app:app
Edit the top of dlna-web.service — it defaults to user pi, path /home/pi/dlna-web, port 8080
sudo cp dlna-web.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now dlna-web
sudo systemctl status dlna-web / journalctl -u dlna-web -f to confirm it's alive

One thing I couldn't verify in this sandbox: it has no internet access, so I couldn't actually pip install waitress and run a live waitress process end-to-end. I did confirm the piece that actually mattered (the app initializes correctly when imported rather than run as a script, which is the whole crux of the systemd fix) — but it'd be worth doing a real smoke test on the Pi itself once you've got it set up, just in case.
